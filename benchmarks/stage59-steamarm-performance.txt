Stage 59 -- SteamARM 0.3.54: Vulkan guest pointers and NTSYNC queue bounds
Date: 2026-10-06. macOS Apple Silicon. Zero VM.

1. VULKAN DESCRIPTORS
  Private native ARM64 ELF probes supplied a synthetic guest-base mapping:
  VkDescriptorBufferInfo at guest address 0x20000000. Both versions called
  the installed native driver, 20000 vkUpdateDescriptorSets calls, followed
  by a vertex-buffer/render pixel readback. This is not an FEX/game FPS test.

  LXRT_NO_LOWPTR_FIXUP=1 disables the runtime's low-pointer fault recovery:
    old shim: SIGSEGV on both drivers, exit 139
    new shim: PASS on both drivers; pixel readback PASS

  Three paired runs, recovery enabled, tracing disabled, microseconds/update:
    MoltenVK old 3.762, 3.608, 3.604; median 3.608
             new 0.046, 0.045, 0.045; median 0.045
    KosmicKrisp old 1.765, 1.818, 1.779; median 1.779
                new 0.014, 0.014, 0.014; median 0.014
  Separate trace runs confirmed at least 32768 / 16384 low-pointer recoveries
  with the old shim respectively; none with the new shim. Trace overhead is
  excluded from the paired timings above.

  Cause: gen_rebase.py included XML <comment> text in a member declaration.
  The registry comment on pBufferInfo contains [_DYNAMIC], so the generator
  classified this pointer as a fixed array and skipped rebasing it. Comparing
  generated wrappers from the same registry/entrypoints changed only that
  pointer field. The original guest field is restored after the driver call.

2. MULTI-DRAW
  The new vkCmdDrawMultiEXT / vkCmdDrawMultiIndexedEXT wrappers rebase low
  draw-array pointers and the optional pVertexOffset. KosmicKrisp: 12 direct
  and 12 indexed draws, with an offset override, pixel readbacks PASS with
  low-pointer recovery disabled. MoltenVK does not offer multiDraw on this
  device; skipped rather than calling an unsupported extension.

3. NTSYNC
  Existing tests/elf/ntsync.c: 17/17 on baseline and new runtime.
  Private 128-thread timeout/churn probe: 3/3 PASS. After waiters retire,
  q_high remains 128 on the baseline and returns to zero on the new runtime.
  Three paired 50000-call zero-time waits after that churn, microseconds/call:
    old 0.640, 0.624, 0.634; median 0.634
    new 0.567, 0.569, 0.582; median 0.569
  Median CPU time decreased 10.25% in this microprobe. No game was measured.
  The change only trims unoccupied tail records while holding the device lock;
  it does not change synchronization state, the protocol, or AUTO selection.

4. ACTUAL FEX AND DRIVER IDENTITY
  Vulkan device fill/readback and three-load reload probes: x86_64 and i386
  through FEX, on MoltenVK and KosmicKrisp, 8/8 PASS.
  MoltenVK 1.4.2, Vulkan 1.3.357, raw driverVersion 10402.
  KosmicKrisp Mesa 26.2.4, Vulkan 1.4.354, raw driverVersion 109060100.
  Driver version fields were not changed for display purposes.

LIMITS
  These results demonstrate reduced CPU/fault overhead, not a 150% FPS gain,
  100 FPS, sub-10-ms frame intervals, zero stuttering, or active monitor VRR.
  No resolution, MSAA, anisotropic filtering, FEX TSO or user settings changed.
  The separate experimental native ARM64 Proton path now passes executable
  probes (stage57); real-game compatibility and performance remain unproven.
