READ THIS TOGETHER WITH stage1-syscall-cost.txt:

* clock_gettime alone is 70% of all syscalls. On native Linux it would be
  answered by the vDSO without entering the kernel at all; under FEX the x86
  client cannot use the guest vDSO, so each one is a real syscall. A ZERO-VM
  runtime answers it in userspace: measured 0.9 ns, against 68 ns for a
  rewritten site that does reach the kernel.

* At 4300 syscalls/s the mechanisms cost, per wall-clock second of one core:
    trap via signal      4300 x 2794 ns = 12.0 ms   (1.2%)
    trap via Mach exc.   4300 x 6317 ns = 27.2 ms   (2.7%)
    rewritten svc        4300 x   68 ns =  0.29 ms  (0.03%)
    rewritten, 70% of them served in userspace = 0.09 ms (0.01%)

  This is the IDLE figure. It is a floor, not a budget: a running game adds its
  own render-thread syscalls and is not represented here. Capture the same
  histogram during a game run before quoting any number as the real load.

* The syscalls to implement first are exactly the head of this list, which is
  much shorter than "Linux": clock_gettime, recvmsg, ppoll, futex, gettid,
  read/write/writev, epoll_pwait, openat, and the signal return path. Those
  nine cover 92% of all calls made.
