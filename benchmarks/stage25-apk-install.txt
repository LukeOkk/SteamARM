F. Robustness and review  (MEASURED)
-------------------------------------
Mutation runs (seeded, scratch scripts, not committed):
- 1,500 random byte mutations (1-8 bytes, 20% also truncated) of the real
  manifests and resource tables of three APKs through:
  - parse_axml and xml_text;
  - ResourceTable, resolve_string and name.
- 3,000 synthetic APKs with one mutated entry through inspect(): the
  manifest, resources.arsc, the adaptive icon XML, the PKCS#7 block, an
  ELF, a PNG.
- On the final code: no exception other than APKError in either run.

Found by these runs, and fixed:
- a <manifest> whose package attribute had become an integer: TypeError.
  A manifest without a string package is now an APKError.
- A string whose bytes were neither UTF-8 nor modified UTF-8: a
  UnicodeDecodeError in the modified-UTF-8 fallback. It now falls back to
  U+FFFD.
- inspect() now turns any stray parse error into APKError.

Codex review (gpt-6-sol, reasoning effort high, read-only sandbox, run
after the above). It reported 13 defects (12 in its final list, the
encrypted-entry one in its notes) and changed no file. Each was checked
here and fixed, with a test:
- v1 took every certificate of the PKCS#7 block as a signer (a chain would
  make an update by the same key look like another signer). Now the
  SignerInfo's certificate, by issuer and serial number.
- v3.1 rotated signers were ignored. They are reported as
  rotatedCertificates, and android-pm accepts either identity.
- A car or television UI-mode string counted as the default label. The UI
  mode type and "notnight" are now qualifiers.
- A deeply nested XML drawable (thousands of levels) raised RecursionError
  through Element.iter(). iter() and xml_text are no longer recursive
  (5,000 levels tested).
- The file vanishing between the report and its SHA-256 let
  FileNotFoundError escape. It is now an APKError.
- Encrypted-flag zip entries let RuntimeError escape. They are now read
  ignoring the flag (the "fake encryption" trick), and a damaged deflate
  stream is an APKError.
- android-pm: an installed package with a lost meta.json, or unaccounted
  non-empty data, skipped the signer check. It is now an unknown signer,
  refused unless --force.
- android-pm: a process killed between the two renames of an update lost
  the installed version. The next command now restores packages/.old-*,
  and a failing second rename puts it back at once.
- android-pm: the data directory was made after the swap, so a failure
  there reported an install that had happened. It is now made first.
- android-pm: a data directory that could not be removed was ignored and
  its kept-data record deleted. Now the data goes first, and on failure
  the app stays installed and the command exits 6.
- android-pm: "org.app\n" passed the package regex ($ before a newline).
  Now fullmatch.
- Launcher: card ids folded dots and underscores (org.foo_bar and
  org.foo.bar shared one card). The id is now "android-" + the package
  name as it is.
- Launcher: the card took the preview's details even if the file was
  replaced before Instalar. android-pm's answer now carries SHA-256, SDK
  levels and permissions, and the card uses them first.

Evidence for the ABI table (docs/APK_SUPPORT.md)
-------------------------------------------------
- arm64-v8a runs natively: lxrun runs aarch64 Linux code today (MEASURED in
  earlier stages). An Android runtime to load an APK's code does not exist:
  UNKNOWN until built.
- No AArch32 on Apple Silicon: UPSTREAM DOCUMENTED for the M1 by the box86
  project ("it only supports 64bits operations. No ARM32 there",
  https://box86.org/2022/03/box64-running-on-m1-with-asahi/). For this M4:
  HYPOTHESIS by extension (sysctl hw.optional lists no AArch32 feature;
  nothing here tried to execute A32 code).
- x86-only through FEX: HYPOTHESIS (FEX runs x86 Linux code under lxrun
  today; inside an Android runtime it would need bionic-side thunks); not
  attempted.
