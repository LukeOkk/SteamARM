1. What is in the branch

nvngx.dll and _nvngx.dll (one source, tools/dlss-metalfx/nvngx.c; Wine
builtins with the prefer-native flag, KERNEL32 the only import [F:
x86_64-w64-mingw32-objdump -p: "DLL Name: KERNEL32.dll"]) stand in for
NVIDIA's NGX core. A game's SuperSampling feature (DLSS 2, 3, 4 -- the
same NGX surface up to SDK 310.x) becomes the channel's ENCODE
(shim/mfx_temporal.h) recorded as a vkCmdUpdateBuffer into the game's own
command buffer: for D3D12 through VKD3D-Proton's ID3D12DXVKInteropDevice1
(BeginVkCommandBufferInterop, GetVulkanResourceInfo1, as
tests/win/d3d12_mfxt_interop.c does), for Vulkan into the game's
VkCommandBuffer with the VkImages of its NVSDK_NGX_Resource_VK. The shim
hands it to KosmicKrisp's kk_steamarm_upscale_temporal (MetalFX temporal);
a refused encode is answered with a vkCmdBlitImage of the colour input
onto the output on the same command list, and the NGX call still
succeeds. DLSSG (frame generation), DLSSD (ray reconstruction) and
multi-frame generation: FrameGeneration.Available = 0,
SuperSamplingDenoising.Available = 0, CreateFeature refuses them with
FeatureNotSupported.

DLSS 1 (2018-2019: an NGX SDK version below 0x13 given to Init, or a 1.x
nvngx_dlss.dll next to the game, STEAMARM_NGX_MODEL or a search next to
the program; STEAMARM_NGX_SPATIAL=1/0 forces) is MetalFX SPATIAL: the DLL
sends the new op SPATIAL (protocol v2, shim/mfx_temporal.h) and the shim
records its own FSR 1 pass (shim/spatial.c: EASU from the colour image
into a private image of the output's size, RCAS when the game asks for a
sharpness above 0, a copy onto the output) with the EASU shader laid out
as KosmicKrisp's FSR-1 hook recognises a game's EASU pass
(shim/scaler/easu_set1.frag: the input at set 1 binding 30, the constants
in a uniform buffer at set 1 binding 1 with con0 first, the shader known
by EASU's own constants 0x7ef07ebb / 0x5f347d74; patches/kosmickrisp-14,
-16, -17: kk_nir_is_fsr_easu, kk_fsr_easu_input, kk_fsr_easu_content,
kk_fsr_metalfx_draw -- a pass over the whole of a plain 2D image from its
origin, one colour attachment, all four channels, no blending, scissor,
depth or stencil). On KosmicKrisp that draw becomes MetalFX's spatial
scaler; on MoltenVK it is FSR 1. The pass needs the textures' own sizes
(EASU's constants), which v2 of the command carries in four of v1's
reserved words. A v2 shim takes v1 and v2 commands, gives the driver v1
only, and writes PROBE's answer back with SA_MFXT_CAP_SPATIAL whatever
the driver said.

Checked against the public headers (github.com/NVIDIA/DLSS main,
include/nvsdk_ngx_defs.h: NVSDK_NGX_VERSION_API_MACRO 0x15; the results
0xBAD0000x; features SuperSampling 1, FrameGeneration 11,
RayReconstruction 13; PerfQuality MaxPerf 0 .. DLAA 5; the create flags
IsHDR 1, MVLowRes 2, MVJittered 4, DepthInverted 8, DoSharpening 32,
AutoExposure 64, AlphaUpscaling 128; the DLSS 4 render presets J 10, K 11,
L 12, M 13 under DLSS.Hint.Render.Preset.*; DLSS.Enable.Output.Subrects
and the subrect keys; nvsdk_ngx_params.h: NVSDK_NGX_Parameter's 17
virtual functions; nvsdk_ngx_defs_vk.h: NVSDK_NGX_Resource_VK; nvsdk_ngx.h
and nvsdk_ngx_vk.h: the entry points' arguments) and against OptiScaler's
nvngx (inputs/NVNGX_DLSS_Dx12.cpp, NVNGX_DLSS_Vk.cpp) for the forms the
static NGX SDK calls in the core: Init(app id, path, device, feature info,
sdk version), Init_Ext(app id, path, device, sdk version, feature info),
Init_ProjectID(project, engine, engine version, path, device, sdk
version, feature info), Init_with_ProjectID(project, engine, engine
version, path, device, feature info, sdk version), and the VULKAN forms
with InGIPA/InGDPA. NVSDK_NGX_VULKAN_RequiredExtensions and the
Get*ExtensionRequirements answer none.

NVSDK_NGX_Parameter's vtable order [F] (clang++ -target
x86_64-pc-windows-msvc on the class as declared in nvsdk_ngx_params.h,
the slot each call loads):
  Set(void*)               (%rax)      slot 0
  Set(int)                 24(%rax)    slot 3
  Set(float)               48(%rax)    slot 6
  Set(unsigned long long)  56(%rax)    slot 7
  Get(void**)              64(%rax)    slot 8
  Get(unsigned long long*) 120(%rax)   slot 15
  Reset                    128(%rax)   slot 16
i.e. MSVC puts overloads of one name in reverse order of declaration:
Set(void*), Set(ID3D12Resource*), Set(ID3D11Resource*), Set(int),
Set(unsigned), Set(double), Set(float), Set(unsigned long long), the Gets
the same way, then Reset -- the order g_param_vt has.

4. Not done / not measured

- No real DLSS game was run: nothing here measures a game's frame rate or
  picture (the task's rules keep this worker off Steam's games).
- The Vulkan NGX path (NVSDK_NGX_VULKAN_*) is implemented, not tested by a
  program (no Vulkan variant of the test yet).
- The DLSS 1 verdict from the SDK version (< 0x13) is inferred from the
  public headers' history [I]; the 2018-2019 SDKs are not public. A 1.x
  nvngx_dlss.dll is the other, independent sign.
- ReleaseFeature's DESTROY frees the shim's spatial objects at once; a
  game that releases while a command buffer using them is still executing
  would race (DLSS games release at a resolution change, after idling the
  GPU) [I].
- The static NGX SDK of a game that takes the registry's NGXCore FullPath
  (System32) looks for _nvngx.dll there, which the tool does not put in a
  game's prefix: such a game shows DLSS unavailable (the sys32 case of the
  test only proves the DLL works when loaded from there).
