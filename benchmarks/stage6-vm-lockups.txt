Two guest-kernel soft lockups in one working day, on the VM the project is
replacing. Both wedged the guest hard enough that ssh stopped answering and
the host process had to be killed; the second one truncated a file the guest
was writing (FEX's freshly linked binary came back 0 bytes). Kept because
'the VM is the stable part' is an assumption this plan keeps meeting.

Host side, both times: the SteamARM process stayed alive holding instance.lock,
gvproxy kept listening, and `ssh -p 2222` answered 'Connection reset by peer' or
timed out. Recovery: kill -9 the host process, relaunch, wait ~150 s for boot,
then `systemctl stop steamfex.service steamarm.service` so the guest stays a
build toolchain. The second lockup left ~/FEX/Build/Bin/FEX at 0 bytes and
cmake's depend files truncated ('Aborted (core dumped)' in cmake_depends);
fixed by deleting the two target dirs and regenerating.
