Stage 22 -- native arm64 Steam client: from abort to the login window (2026-09-29)
================================================================================

ZERO-VM. No FEX for the client. Host: Mac mini M4, 16 GB, macOS 27.0, X on
display :2 (scripts/run-x11-native.sh, rootless XQuartz build).
Client: steamrtarm64/steam, version 1788652215 (unchanged all session; the
156 files of steamrtarm64/ have the same sha256 before and after, MEASURED).

Result (MEASURED, run E18 below): with this stage's root and runtime changes
and the --jitless workaround, Valve's native arm64 client reaches BrowserReady
8 s after start and maps its "Sign in to Steam" window (700x440, class
steamwebhelper) on :2 at 10 s; it stays up (150 s run, 1 webhelper launch, 0
restarts, no FATAL in cef_log.txt). A screen capture of the region shows the
complete login page (account/password form and a live sign-in QR code, i.e.
the webhelper's network process reaches Valve's servers). Login itself was not
attempted.

Remaining blocker (MEASURED + VERIFIED IN SOURCE): without --jitless every
webhelper renderer dies on its first JIT'd call -- V8 asks for
read-write-execute code pages and runtime/dispatch.c (do_mprotect_inner, "RWX
outside MAP_JIT: granted as RW") gives it read-write; the renderer then
executes a non-executable page (SIGBUS, KERN_PROTECTION_FAILURE, pc == fault
address). 1137 renderer launches in 90 s, no window (E17).

How to reproduce
----------------
  make lxrt
  scripts/mkarmroot.sh                      # keeps <root>/tmp (the client home)
  scripts/run-steam-arm64.sh --jitless      # --for SECONDS to stop by itself
The client must already be in ~/SteamARM-roots/armroot/tmp/armhome (stage 21).

Runtime changes (separate commits, each measured)
-------------------------------------------------
1. x18: "mrs x18, nzcv" / "msr nzcv, x18" rewritten instead of poisoned
   (runtime/x18.c). libcef.so keeps a carry in x18 at text vaddr 0x63cf638 /
   0x63cf684 (VERIFIED IN SOURCE, llvm-objdump). The trampoline's
   stp/mrs tpidrro_el0/and/ldr ... str/ldp do not touch NZCV.
2. x18: LDAR/STLR (ordered, no exclusive monitor) on x18 rewritten instead of
   refused as "exclusive" (runtime/x18.c). libcef.so: ldar w18, [x18] at
   0x2e05a84 and 0x3b1037c, ldar w18, [x16] at 0x3b1c5f8. LDXR/STXR/LDAXR/
   STLXR and an SP base stay refused.
3. mmap of a file at an offset on a 4 KiB guest page but not a 16 KiB host
   page, without MAP_FIXED (runtime/dispatch.c do_mmap): mapped from the host
   page below, the guest gets the address of its offset. Darwin returned
   EINVAL before.
Tests: build/x18_check --self-test PASS (the new NZCV cases fail against the
old x18.c with 4 failures, the LDAR cases against the NZCV-only x18.c with 3).
tests/elf/run.sh with the final build: 37 passed, 0 failed (8.2 s).
The x86 route (FEX Steam) was NOT re-run with this build: UNKNOWN.

Still open
----------
- V8 JIT (the blocker above). Direction (HYPOTHESIS, not built): for native
  aarch64 guests, give an mprotect(RWX) range MAP_JIT semantics driven by
  jit.c, as anonymous RWX mmaps already get; under FEX the RW grant must stay
  (x86 code is never executed by the host). Until then --jitless.
- XOpenIM() still fails with LANG=es_MX.UTF-8 (no es_MX glibc locale in the
  root; HYPOTHESIS: harmless, no input method needed for the login page).
- steam-runtime-launcher-service not found (client logs "possible problem,
  disabling"; non-fatal).
- "[lxrt] mremap: file-backed range ...: not supported yet" 1-2 times per run
  in the webhelper; effect UNKNOWN.
- The GPU process cannot initialise GL on XQuartz (ANGLE: "Cannot create an
  OpenGL ES platform on GLX without the GLX_ARB_create_context extension");
  the webhelper falls back to software compositing ("Disabling GPU
  acceleration due to runtime detect").
- The head of a host page mapped by runtime change 3 stays mapped until the
  whole host page is unmapped (by design of the change; leak size <= 12 KiB
  per such mapping).
- Proton ARM64 itself: unchanged from stage 21 (not attempted).
