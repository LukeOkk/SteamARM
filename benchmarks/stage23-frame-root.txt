Deriving the root: scripts/mkframeroot.sh
-----------------------------------------
  scripts/mkframeroot.sh [--adopt] [--home-from DIR] [SRC [OUT]]
APFS clone of the extraction (cp -Rc; same volume required, OUT inside SRC
refused, SRC must say ID=steamos), then only:
  etc/resolv.conf      nameservers (item 2)
  etc/localtime        the host's zone, so the client's logs use the Mac's
                       clock (the image says America/Los_Angeles)
  .lxrt-guest-env      __GLX_VENDOR_LIBRARY_NAME=mesa,
                       MESA_LOADER_DRIVER_OVERRIDE=swrast,
                       LIBGL_ALWAYS_INDIRECT=1 (item 1)
  .lxrt-frameroot      marker: source BUILD_ID, date, the list above
  dev/shm, run         empty directories, if the image lacks them
It keeps <root>/tmp (the client home, tmp/armhome) and <root>/opt/apps
across rebuilds (built as OUT.new, swapped at the end; an interrupted swap is
recovered on the next run), links $STATE/arm64root, and --home-from copies a
client home (rsync, without steamapps/common) when the root has none. The
stage 22 hand clone was rebuilt with --adopt: 32 s (clone 23 s), MEASURED.
Nothing extracted from the image is committed or shipped.
The environment file is read by scripts/run-steam-arm64.sh and
scripts/run-native.sh (scripts/guest-env.sh; a variable already set wins), so
the launcher's runner gets it too (run N1).
Integrity (MEASURED): after all the runs, `rsync -rlni --delete` from the
extraction to the derived root (tmp/ and sys/ excluded; the runtime writes
sys/devices/system/cpu, runtime/sysfs.c) lists only the overlay (4 lines:

What differs on the Frame root (MEASURED, client logs; not in the way)
------------------------------------------------------------------------
The client takes its SteamOS paths: SteamOSManager ("daemon not present"),
CGamescopeController, the steamos telemetry service, NetworkManager
("IClientNetworkDeviceManager::IsInterfaceValid took too long: 2512 msec"),
gpu-trace, /usr/bin/steamos-polkit-helpers/steamos-update (which runs
atomupd-manager), steamos-devkit-mode --disable, timedatectl, dbus-launch,
a missing jupiter-dock-updater. atomupd-manager (Valve's, 64 KB) cannot reach
the system D-Bus ("GLib-GIO-CRITICAL ... G_IS_DBUS_CONNECTION") and then
reads address 0x8: "[lxrt] SIGSEGV at pc ... image+0x1878c addr 0x8", 4 times
per run. HYPOTHESIS: the same NULL dereference happens on Linux without a
system bus; the runtime only reports it. The client carries on. The update UI
logs "X Error of failed request: GLXBadCurrentWindow" and continues.
The periodic "Background update loop checking for update" about once a
second after 2 min of running is the same on the Fedora root (stage 23 E5/E7
logs: 193-221 per run): not root-specific.

Still open
----------
1. The restart of the first webhelper within a second of its start ("Restart
   webhelper process, counter 2" from chromehtml.so's CChromeIPCClient):
   cause UNKNOWN. It costs 5 renderer launches; its cost in time is not
   measured. Its two zygotes then live on with parent 1 until the session
   ends (F7): on Linux a zygote
   exits when its browser's socket closes (HYPOTHESIS for Chromium 126);
   why they do not here is UNKNOWN.
2. Start-up is 5-7 s slower than on the Fedora root. HYPOTHESIS: the SteamOS
   paths above (NetworkManager's 2.5 s IPC timeout, the restart in 1).
3. No Vulkan device in this root as built (freedreno only). The shim gives
   one (V1); whether the client and its webhelper behave with it is
   UNKNOWN, so it is not installed.
4. GL is indirect GLX 1.4 over the X protocol: enough for the client's vgui
   windows; the webhelper composites in software, as on the Fedora root.
5. The home is the stage 22 copy of the Fedora root's home, now on the
   steamdeck_stable build. The image's own bootstrap
   (usr/lib/steam/steam.tar.zst) was not used.
6. The launcher's built-in "steam-arm64" entry is unchanged: it still names
   /tmp/lxrt-armroot. What it should become is below.
