Result
------
1. (MEASURED) The x18 REWRITER IS STILL NEEDED with the keep build. xnu keeps
   x18 for an SDK-12.3 binary only in the process it exec'd; a child of
   fork() (no exec) has x18 zeroed again, and so do threads created in that
   child and a grandchild (probe below, and tests/x18_preserve/run.sh now
   measures it). Guests fork without exec all the time: Chromium's zygotes
   (Steam's webhelper, Heroic), Android's zygote, shells. With the keep build
   and LXRT_NO_X18=1 (the pass off) the native Steam client never shows its
   sign-in window and Heroic exits at start: both lose their forked GPU
   process ("GPU process isn't usable. Goodbye."). So the runtime does NOT
   skip the x18 pass when the kernel keeps x18; no start-up detection was
   added (step 2 of the plan was conditional on the matrix passing without
   the pass, and it does not).
2. (MEASURED) The keep build passes the whole matrix at least as well as the
   sdk27 build (table below), so it is the Makefile default now
   (LXRT_KEEP_X18=0 opts out). What it adds: code the runtime never rewrites,
   a JIT's (Linux HotSpot's C1/C2, llvmpipe: stage 24), keeps x18 in the
   process lxrun was exec'd as -- also across guest signal handlers, after a
   runtime fix (item 4). In forked children it does not.
3. (MEASURED) V8's TurboFan crash of stage 24 is found and fixed. The x18
   planner rewrote `br x18` through x16, as it does blr and ret; V8's
   TurboFan dispatches a jump table with `br x18` while w16 is live and read
   the target address back as w16. The trampoline now keeps every general
   register. TurboFan works on both builds (Node reproducer 10 of 10 each,
   0 of 3 before), and Heroic runs without --js-flags=--no-opt (launcher
   entry changed; phase_b 3 of 3 plus a Quit cycle).
4. (MEASURED) A guest signal handler used to leave the hardware x18 set to
   the VIRTUAL x18 on return. With the keep build that corrupted a JIT's
   live x18 at the first signal (HotSpot takes SIGSEGV in compiled code for
   safepoint polls and implicit null checks): generated code lost x18 after
   1 signal at 7492467, keeps it through 100-122 handlers now.

TurboFan: how the cause was found (MEASURED)
--------------------------------------------
tests/heroic/turbofan.sh (new; the stage-24 T2 reproducer: Heroic's Electron
43 binary as Node, ELECTRON_RUN_AS_NODE=1, LXRT_X18_ALL_TEXT=/opt/apps/heroic/),
at 7492467, 3 runs each:
  sdk27, pass on               small 0/3: SIGTRAP at image+0x6c5ecf4 (as T2)
  keep,  pass on               small 0/3: the same
  keep,  LXRT_NO_X18=1         small 3/3 ok
("heavy", 60 functions from new Function, passes 3/3 everywhere; it is not
stage 24's T3, whose script is not in the tree.) With the kernel keeping x18
the rewriting became the only difference, and a site left alone stays correct,
so the sites could be bisected: a scratch build rewrote only x18 sites at
.text offsets [lo, hi) of the heroic image (the libraries always). 22 steps,
83 s, converged on .text+0x3e6f600..+0x3e6f680. Rewriting single
instructions of a sequence is not meaningful (the others then use the other
x18), so the sequence was read instead (llvm-objdump, heroic vaddr 0x691f640):
     691f640  sub  w16, w13, #0x38f          <- w16 computed
     691f648  cmp  w16, #0x7b
     691f64c  b.hi 0x691f660
     691f650  adr  x18, 0x691f668            <- rewritten
     691f654  ldrb w0, [x5, x16]
     691f658  add  x18, x18, x0, lsl #2      <- rewritten
     691f65c  br   x18                       <- rewritten: target in x16
     691f668  bti  j ...  691f670 bti j
     691f684  cmp  w16, #0x7c                <- w16 read after the branch
Rewriting the three jump-table sites alone crashed 4 of 4 runs. The BR plan
(runtime/x18.c at 7492467) loaded the target into x16 and branched with
`br x16`: correct for blr and ret, where the procedure call standard lets
x16 die, wrong for a jump table inside a function. TurboFan's `cmp w16`
then compared an address, took the wrong path, and a graph CHECK fired
later (CFGBuilder::ConnectBlocks in stage 24).

The fix (cc54e05, runtime/x18.c plan_br, runtime/signal.c):
  stp x16,x17,[sp,#-16]!; mrs x17,tpidrro_el0; and x17,x17,#~7;
  ldr x16,[x17,#slot]; adr x17,D; stp x17,x16,[sp,#-16]!; add x17,sp,#16;
  ldp x16,x17,[x17]; add sp,sp,#32;
  A mrs x18,tpidrro_el0; B and x18,x18,#~7; C ldr x18,[x18,#slot]; D br x18
No general register changes. The last four words use the hardware x18.
Where the kernel zeroes it (every sdk27 process, every fork child of a keep
process) an exception between A and D leaves 0: C then faults on a page-zero
address and the runtime restarts the trampoline from its first word (x16, x17
and sp are the guest's again, so this is idempotent), or D branches to 0 and
the runtime resumes at the target the trampoline marked at sp-32 (checked:
the mark names a real D and equals the virtual x18; cleared once used). A
guest signal arriving on A..D restarts the trampoline before the guest frame
covers the mark. Both recoveries are checked only for a pc in a trampoline
pool (or 0) and a hardware x18 of 0, so W^X flips pay nothing more.
Residual (HYPOTHESIS, not observed): a guest's own jump to address 0, in the
same frame right after a br x18 dispatch, with the virtual x18 unchanged,
would be taken for the second case.

After the fix (5 runs each): sdk27 small 5/5, heavy 5/5; keep 5/5, 5/5;
keep + LXRT_NO_X18=1 5/5, 5/5. LXRT_X18_STATS=1 on the sdk27 build (new): 5-12
restarts after a fault per 48M-dispatch run of X18_JUMP_TABLE, 0-1 branches
to 0 recovered.

Build and CI (292236a)
----------------------
- LXRT_KEEP_X18 ?= 1. The link adds -mmacosx-version-min=12.0
  -Wno-unguarded-availability-new -Wl,-platform_version,macos,12.0,12.3; it
  records the version only, no 12.3 SDK is needed (the same flag built the
  SDK-12.3 probe on the macos-15 runner in stage 20, MEASURED there).
- If that link fails, the rule links against the current SDK and prints
  "lxrun: linking as SDK 12.3 (LXRT_KEEP_X18=1) failed; linking against the
  current SDK instead. ..." (MEASURED with a bogus linker flag passed in:
  "ld: unknown options", then the message, then "sdk 27.0"). Every build
  prints "lxrun: LC_BUILD_VERSION sdk 12.3: the kernel keeps x18 for JIT
  code" (or "... zeroes ...").
- build/.lxrun-flavor holds LXRT_KEEP_X18=<n> and is rewritten only when it
  changes, so `make lxrt LXRT_KEEP_X18=0` and back rebuild lxrun (MEASURED:
  sdk 27.0, then sdk 12.3; an unchanged make rebuilds nothing). A first
  version with one stamp file per value was not seen as newer by macOS's
  GNU make 3.81 ("Prerequisite ... is newer than target" then "No need to
  remake target"): not kept.
- .github/workflows/macos.yml: a step after the build prints lxrun's
  recorded SDK and raises a warning annotation when it is 13 or later.
  scripts/make-release.sh refuses a Makefile that no longer defaults to
  LXRT_KEEP_X18=1 (the package ships the source; the user's Mac builds lxrun
  with scripts/setup.sh). The CI run itself was not observed (no push).
