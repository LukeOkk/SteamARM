Stage 25 -- Android 11 userspace under lxrun: bionic programs, and where ART stops (2026-09-29)
==============================================================================================

ZERO-VM. No virtual machine, no guest kernel, no FEX. Host: Mac mini M4,
16 GB, macOS 27.0 (26A428). Base commit 53432eb. Every guest below is an
unmodified Android 11 arm64 binary from Waydroid's LineageOS 18.1 image,
run by lxrun as a macOS process. Nothing was signed in to, no Google
component was downloaded, no Steam client was started. Other agents ran
guests on the same Mac (a FEXServer started by another session was running
throughout); every process below was started and stopped by this session
only, by its own PID. Home paths are written as ~.
Labels: MEASURED, VERIFIED IN SOURCE, UPSTREAM DOCUMENTED, HYPOTHESIS, UNKNOWN.

Result
------
MEASURED:
1. bionic runs under lxrun. linker64 (as a program and as PT_INTERP),
   toybox (ls, echo, uname, id, cat, grep, seq, paste, date, wc,
   sha256sum, md5sum), mksh (arithmetic, loops, $(...) with fork, pipes),
   getprop and ART's dexdump run from the Android root and give the right
   output; toybox's sha256sum of framework.jar equals the Mac's shasum.
   Start-up: toybox true 53-58 ms median, mksh -c true 40 ms.
2. That took seven runtime changes (R1-R7 below): sub-page mremap (bionic's
   CFI shadow), PR_SET_TAGGED_ADDR_CTRL refused (bionic's tagged heap),
   BoringSSL FIPS module's TPIDR_EL0 reads kept byte-for-byte (its
   integrity self-test), msync, rt_tgsigqueueinfo, clone TLS inheritance
   and refusing a thread without CLONE_FILES.
3. ART cannot start, with or without the JIT: its heap must be mapped below
   4 GiB (32-bit compressed references), and macOS maps nothing below 4 GiB
   in an arm64 process. dalvikvm64 and dex2oat64 both abort with
   "Could not find contiguous low-memory space." / heap.cc:493
   "Check failed: non_moving_space_mem_map.IsValid() ... Out of memory".
   So Hello.dex (built on the Mac with D8) was never executed by ART, and
   -Xint against JIT, wall time and the CPU loop's correctness on ART could
   not be measured. This wall is below binder: no Java process of Android
   (zygote, system_server, any app, the Play Store) can start under the
   in-process design until ART's heap can live above 4 GiB
   (docs/ANDROID_RUNTIME_ARCHITECTURE.md, "The ART heap wall").

Runtime changes (all in this stage's commits; tests below)
-----------------------------------------------------------
R1  runtime/dispatch.c do_mremap_subpage: mremap of 4 KiB guest pages that do
    not fill their host pages (addresses not 16 KiB-aligned, or ranges
    runtime/subpage.c tracks): a private anonymous mapping through do_mmap,
    the bytes copied (a copy-on-write alias, so any protection reads), the
    protection through do_mprotect, the source unmapped through do_munmap.
    Shared sources are refused (ENOMEM). runtime/mremap.c gains the copy
    and host-protection helpers, runtime/subpage.c lxrt_subpage_prot_at.
R2  prctl(PR_SET_TAGGED_ADDR_CTRL / PR_GET_...) -> EINVAL.
R3  runtime/tls.c "kept TLS reads": elfsect.c finds BoringSSL's
    BORINGSSL_bcm_text_start/end in .dynsym (after a memmem of .dynstr) when
    a library is mapped; rewrite.c leaves the TLS reads there as they are
    (only reads; every other site kind is still rewritten); a load or store
    in that range whose base register holds a value Darwin leaves in
    TPIDR_EL0 (below 4 GiB or at/above 2^48) is fixed in the fault path by
    putting the guest's thread pointer in that register. LXRT_TLS_KEEP=0
    turns it off. The self-test is not bypassed: it hashes the module's
    original bytes and passes on them.
R3b The first version also wrote the guest's pointer into TPIDR_EL0 so that
    the next reads would not fault. With an lxrun built against the current
    SDK (sdk 27.0) toybox then crashed inside the runtime's own malloc
    (sample(1): lxrt_proc_translate -> materialise -> _xzm_malloc_large_huge
    -> xzm_segment_group_alloc_chunk -> _sigtramp -> host_handler, delivered
    to bionic's crash handler, then a hang in its futex); the 12.3-SDK build
    ran. Without the write: 7 of 7 with both builds. A plain Mach-O that
    puts a pointer in TPIDR_EL0 and makes 20,000 mallocs did not crash with
    either SDK, so the mechanism is UNKNOWN (HYPOTHESIS: Darwin's allocator
    or signal path reads TPIDR_EL0 under the conditions of a guest thread).
    Also measured (scratch tpidr_check.c): a TPIDR_EL0 written by a process
    is lost after usleep and 1,567-1,592 times in a 1.5 s busy loop, with
    the 12.3 SDK as with the current one: the x18 compatibility does not
    extend to it.
R4  msync: Linux flags and alignment checks, ENOMEM for an unmapped page,
    0 for the low 4 GiB (reserved), MS_SYNC written back through Darwin.
R5  rt_tgsigqueueinfo (240) and rt_sigqueueinfo (138), sent like tgkill and
    kill (the caller's siginfo payload is not carried): bionic's abort()
    raises SIGABRT this way.
R6  clone of a thread without CLONE_SETTLS starts with the parent's thread
    pointer (Linux copies TPIDR_EL0).
R7  clone of a thread without CLONE_FILES -> EINVAL: a Darwin thread cannot
    own a descriptor table. glibc's and bionic's pthread_create always pass
    CLONE_FILES.
Diagnostics: LXRT_FAULT_LOG=1 (a fault that goes on to the guest, with its
registers, without a syscall trace), LXRT_TLS_KEEP_LOG=1, and
tests/android/logd.py, a host stand-in for logd's write socket
(<root>/dev/socket/logdw): Android's error messages go to logd, not stderr.

What was not done
-----------------
- ART never executed Java (the heap wall); no JIT, no boot image, no odex.
- No property service, no init, no logd (tests/android/logd.py stands in for
  its socket), no binder, no servicemanager, no zygote.
- linkerconfig is ET_EXEC and cannot run; the linker ran with no
  ld.config.txt (default namespace, /system/lib64 and /vendor/lib64 search
  paths), which is enough for toybox, mksh and ART's tools.
- The 1,684 32-bit arm files cannot run on Apple silicon (no AArch32).
- Crash dumps (crash_dump64 needs ptrace and a thread with its own
  descriptor table): an abort exits with status 1.
