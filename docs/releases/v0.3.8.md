**Each Android app opens in its own Mac window.** An APK's card now opens the app in a window of its own, titled with the app's name, instead of one window holding all of Android: SteamARM draws Android's windows itself with `steamarm-wlmac`, a display server written for macOS, and Android runs in its multi-window mode. Clicks and keys reach the app (measured: a click opens a game in Simple Solitaire, keys arrive as themselves), and closing the app's window ends the Android session. The previous single window is still available (`ANDROID_SESSION_COMPOSITOR=weston`).

**Sound from compressed files.** Games' effects and music and Android's system sounds need Android's media services; they now run: the media server and the codec service (32-bit, possible since 0.3.7's small process numbers), with the software decoders. Measured: an Ogg sound decodes in Android, and Android's media player plays one to the Mac's speakers.

**Runtime:** a program whose crash handler never fixes a crash is now ended, as Linux would end it, instead of spinning a processor core forever (an Android service did).

**Android's network survives a restart of Android's system services:** it registers again (measured: back 33 s after a restart).

Steam from the launcher: x86 main window at 96 s and 91 s (2 of 2); native ARM64 sign-in window at 15-26 s (Fedora root, 3 of 4 starts: once its web helper crashed in SteamARM's runtime; stop and start it again) and 20 s (Steam Frame root).
