**fsync and esync work.** Proton's two fast ways to synchronize a game's threads now run on SteamARM's runtime. fsync needs a Linux call (`futex_waitv`) that the runtime did not have, so Proton quietly turned fsync off; it is now implemented on macOS's own wait primitives, between processes too. esync's objects, which Wine's server hands to each program, used to arrive broken in the receiving program; they now arrive whole. Both are **Experimental** in **Configuración → Sistema → Sincronización**: they work in SteamARM's own tests, but no game has been tried with them yet.

**OpenGL on the GPU, and WineD3D.** OpenGL now runs on the Mac's GPU: Mesa's Zink driver turns it into Vulkan, which SteamARM already sends to Metal through MoltenVK. With it, **OpenGL (WineD3D)** in **Configuración → Gráficos** is no longer greyed out: it is **Experimental**, Wine's own Direct3D on that OpenGL (OpenGL 3.2; Direct3D 9 and 11 test programs draw). It is offered only once Setup has rebuilt the window server (see below). AUTO still uses MoltenVK.

**Every OpenGL program in a native window renders directly.** The window server described its pixel formats in a way Mesa could never match, so every Linux OpenGL program silently fell back to an old, slow path (Apple's OpenGL 2.1 through the window server). Setup rebuilds the window server with the fix and restarts it when nothing is running.

**Stopping Steam or a game no longer ends the Android session.** Stopping Steam, or a game from the launcher, used to stop every program SteamARM was running, Android apps included.

**Android apps can delete folders,** and files an app creates belong to it (git in Termux works); Steam no longer connects to an Android helper process by mistake.

**Settings no longer lists Lightning JIT or Apple Hypervisor,** which do not exist in SteamARM; they will appear if they ever become usable.

**Tested on a real Mac (M4, macOS 27):** tests/elf 103/103; i386 18/18; Windows programs 14/14 (Direct3D 9, 11 and 12 through DXVK and VKD3D-Proton, Direct3D 9 and 11 through WineD3D); Vulkan and OpenGL 4/4; native display server 4/4; Python and launcher tests pass; Android 88 passed with 2 expected failures. x86 Steam reached its main window 4 times in 4 (60 s each). Records: `benchmarks/stage37-sync-fsync-esync.txt`, `benchmarks/stage38-opengl-zink.txt`.

**Known:** a 32-bit Direct3D 9 program through WineD3D stops with an error as it exits (after drawing). KosmicKrisp cannot run OpenGL through Zink (a bug in KosmicKrisp 26.2.3), so WineD3D always uses MoltenVK.

**Pre-release.** Games are still not verified. Google Play Store has not been run.
