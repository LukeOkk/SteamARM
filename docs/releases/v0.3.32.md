**Steam's own audio settings work, the Mac's microphone is no longer held open, and Steam starts without stalling.**

What was done:
- **Steam's audio settings and voice now have devices.** The Steam client manages its sound through PipeWire, which SteamARM did not provide. SteamARM now runs PipeWire inside the ARM64 system with two devices, "Mac (sonido)" and "Mac (micrófono)", that lead to the Mac's own sound through SteamARM's PulseAudio server. Games keep sending their sound straight to that server, as before, so nothing changes for them. Idle, it uses no CPU.
- **The microphone is only opened when something records.** SteamARM's sound server kept every input of the Mac open for as long as it ran, so macOS showed the microphone as in use (the orange dot) even when nothing was recording. Devices that nobody uses are now closed after 3 seconds.
- **No more start-ups that stall without a window** (about one in sixty before). One file-flushing operation that Steam's web browser uses all the time was 17 times slower than it needed to be on SteamARM's disk image (150-300 ms per call while Steam was starting). In 21 starts in a row since, the main window came up every time.

Everything in 0.3.31 is included.

**Tested on a real Mac (M4, macOS 27):** runtime tests 108/108, settings tests 15/15 (one new), Python tests passing; PipeWire's devices listed by `wpctl status` with Steam running.

Update: drag the new SteamARM.app over the old one, open it, and click **Instalar** in the banner.
