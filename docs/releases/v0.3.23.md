**Native arm64 games in Steam Frame.** For an arm64 client Steam runs games such as Counter-Strike 2 through Valve's Steam Linux Runtime 4 for arm64, whose container tool (pressure-vessel) is built in a way macOS cannot load. SteamARM now does that tool's job itself: the game starts in the Steam Frame system, natively, without translation and without a container. Tested with an arm64 Vulkan test program launched exactly as Steam launches a game.

**Vulkan in the Steam Frame system works through its own loader.** Programs of the Steam Frame system that load Vulkan the standard way (games, and the Steam window's acceleration) were sent back into the loader by SteamARM's driver and hung, or fell back to Chromium's software Vulkan. Fixed: they now reach MoltenVK or **KosmicKrisp** for real.

**The Steam window on the GPU, for real.** With the fix above, "Interfaz de Steam ARM64 acelerada por GPU" (on by default) runs Steam's window on Metal through the Vulkan driver you choose: MoltenVK or KosmicKrisp.

**KosmicKrisp: every scaling filter works.** FSR, whole pixels and bilinear enlarge a lower resolution on KosmicKrisp; MetalFX, which only MoltenVK can feed, uses bilinear there.

Everything in 0.3.22 is included.

**Tested on a real Mac (M4, macOS 27):** runtime tests 104/104, Vulkan tests 6/6 on MoltenVK and on KosmicKrisp, Windows tests 21/21; on KosmicKrisp the Direct3D 9/11/12 programs run at 152-158 fps and every scaling filter fills the screen correctly. Records: `benchmarks/stage47-kosmickrisp.txt`, `benchmarks/stage48-native-arm64-games.txt`.

**Pre-release.** Counter-Strike 2 itself has not been run by SteamARM's tests (its files were still downloading); 32-bit Direct3D 12 does not work on KosmicKrisp yet.
