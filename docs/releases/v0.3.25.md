**Counter-Strike 2 runs from the Steam Frame client**, as its native Linux version (no Wine): a match against bots on Dust II at 72-76 frames per second (median; M4, the game's own settings), the main menu at 80-82. Before this release it never drew a frame.

To use it: in Steam, open the game's Properties > Compatibility, force **"SteamARM: Linux x86 via FEX (experimental)"**, and let Steam download the Linux version. Choose **KosmicKrisp** in SteamARM's graphics settings.

What was done:
- **A new compatibility tool for native Linux x86 games.** Steam's ARM64 client downloads a game's Linux build and SteamARM runs it in Valve's Linux runtime under FEX.
- **SteamARM now builds its own KosmicKrisp** (Mesa's Vulkan driver for Metal) with four fixes, and uses it instead of Homebrew's when the graphics setting is KosmicKrisp. The update builds it (a few minutes). The fixes: the driver kept tens of gigabytes of GPU memory with games that use thousands of command buffers; a game's third pool of occlusion queries could not be created; some vertex shaders were refused; and render passes that follow one another on the same targets are now drawn as one, which is what took the match from about 50 to about 75 frames per second.
- **A wait that should have lasted "forever" returned at once.** This is what kept Counter-Strike 2 from drawing anything: its worker threads spun instead of sleeping. Any program that waits longer than 71 minutes at a time was affected.
- **A fullscreen game no longer minimizes itself** when it starts without the keyboard focus (it then drew 10 frames per second for nobody).
- The compatibility tools installed in Steam are kept up to date with SteamARM.

**Not there yet:** 170-200 frames per second. Three limits remain, all measured: frames are presented at most every second refresh of the display (82.5 per second on a 165 Hz display), the game issues about 135 render passes per frame after merging, and its main thread is translated x86 code. The first minute on a map stutters while shaders are compiled. Steam's shader pre-caching stays off.

Everything in 0.3.24 is included.

**Tested on a real Mac (M4, macOS 27):** runtime tests 106/106, Windows tests 21/21, Vulkan tests 11/11 (MoltenVK, Homebrew's and SteamARM's KosmicKrisp), compatibility-tool tests 36/36, Python tests 151/151. Measurements: `benchmarks/stage51-cs2-linux-native.txt`.

**Pre-release.** Only local play against bots was tested. Proton ARM64 still does not start (needs memory macOS does not give); Windows games go through "SteamARM: Proton x86 via FEX".

Update: drag the new SteamARM.app over the old one, open it, and click **Instalar** in the banner.
