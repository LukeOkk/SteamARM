**Resolution scale (experimental).** **Configuración → Gráficos → Escala de resolución** is no longer greyed out. With it on, a game that offers resolutions lower than the screen's draws at the one you choose in the game (faster) and is stretched over the whole screen. It uses Wine's display-mode emulation in the games' prefixes; SteamARM applies it when Steam or an app starts with no game open, and a newly installed game gets it from its second start. The stretch is bilinear: AMD's FSR itself is not in any installed Proton.

**Direct3D 10/11/12 games no longer stall on a lower resolution.** When a game's picture was smaller than its window, every frame was rejected by the Vulkan driver and the game kept rebuilding its swapchain (4 frames in 2.5 seconds in the test). SteamARM now asks the driver to stretch the picture.

**MSync explains itself.** It stays unavailable: it is a macOS Wine feature on Mach semaphores that Linux Proton cannot use. Its idea, waiting in the macOS kernel without going through wineserver, is what fsync already does in SteamARM; Settings now says to choose fsync.

**Lightning JIT and Apple Hypervisor are not added.** A "Lightning JIT" could only be FEX with speed settings, and those showed no measurable gain (FEX already runs the x86 benchmark at native speed here), so it would be a placebo. Apple Hypervisor is a virtual machine, which SteamARM does not use.

Everything in 0.3.19 is included.

**Tested on a real Mac (M4, macOS 27):** the test program asks for 1280x720 full screen on a 1920x1050 screen: it draws at 1280x720 in a window that covers the screen, 376 frames in 2.5 seconds with DXVK. Windows tests 15/15, Vulkan tests 6/6. Record: `benchmarks/stage43-settings-presets.txt`.
