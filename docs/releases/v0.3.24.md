**The Steam Frame window is smooth.** It used to change once every one or two seconds, and was black with GPU acceleration on. It now follows your display's refresh rate: 157-160 frames per second on a 165 Hz display in our animation test, against 1 before, drawn on the GPU through **KosmicKrisp** (or MoltenVK), at about 1 % CPU when idle.

What was wrong, all fixed:
- **SteamARM's X server told programs the desktop refreshed once per second.** Steam's window (Chromium) paces itself by that number. It now reports the real rate of your display.
- **Steam's GPU process could not compile shaders.** Chromium starts it in a way that left it without access to Metal's shader compiler, so every shader failed and the window stayed black. SteamARM now reconnects it, with MoltenVK and KosmicKrisp alike.
- **The acceleration settings reached every helper process of Steam's window** and stopped them from starting. They now go only to the main one, which passes them on.

The "OpenGL GLX indirect rendering" warning no longer appears when the Steam Frame and Steam ARM64 clients start.

Everything in 0.3.23 is included.

**Tested on a real Mac (M4, macOS 27):** runtime tests 104/104, new Vulkan shader tests 6/6 (MoltenVK and KosmicKrisp, including the way Chromium starts its GPU process), X server tests 3/3, Python tests 148/148. Record: `benchmarks/stage49-frame-ui-smooth.txt`.

**Pre-release.** The X server change takes effect once SteamARM rebuilds and restarts its X server, which the update does when no program is running. Moving and resizing the Steam window with the mouse is not there yet.

Update: drag the new SteamARM.app over the old one, open it, and click **Instalar** in the banner.
