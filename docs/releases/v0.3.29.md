**The game window no longer freezes or goes black after a change of the video settings, and V-Sync works properly.**

What was done:
- **"The window freezes or goes black every so often; I have to switch windows for it to update."** The graphics driver (KosmicKrisp) kept a reference to every image it put on screen, and to one it had been given and not shown yet, so those images never came back to the window's pool of three. After the second change of a video setting (each one makes a new swapchain) the game had no image left to draw into and waited a second for each frame — a black or frozen window. Switching windows made the game try again, which sometimes worked. Fixed in the driver (patch 07); a new test remakes the swapchain eight times (fullscreen on and off, borderless, resizes) without a stall.
- **The same leak cost more than half the frame rate:** Counter-Strike 2 at 1920x1080 with everything at its highest, V-Sync on, in a match against nine bots: **80 frames per second median** (was 35) on an M4.
- **V-Sync on now keeps the game's full speed.** A game asking for V-Sync used to wait at every frame until the previous one had been shown (23 fps instead of 33 when the GPU was the limit). SteamARM now paces it the same way as without V-Sync, but never drops a frame and never tears: every frame appears exactly on a display refresh, and a game faster than the display is held to its rate. `LXRT_VK_MAILBOX=immediate` restores the old behaviour.

Everything in 0.3.28 is included (picture always in front of its window, real fullscreen, the install fix).

**Tested on a real Mac (M4, macOS 27):** Vulkan tests 20/20 (two new), Python tests 151/151, the driver built from clean sources with all seven patches. Measurements: `benchmarks/stage54-drawable-retain.txt`.

**Still open:** a 32-bit Windows program on "OpenGL (WineD3D)" hangs at start with the full-display X screen (`STEAMARM_X11_FULL_DISPLAY=0` avoids it).
