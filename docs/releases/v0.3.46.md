**Counter-Strike 2: no more black screen after a kill, whole palm trees, and Steam no longer eats memory the longer it stays open.**

What was done:
- **Black screen after every kill, then a frozen game: fixed.** 0.3.44 started using Apple's MetalFX for CS2's "Calidad ultra" upscale, recognising that pass by the shape of its shader. The game draws other things with the same shader (effects blended over the picture), and MetalFX replaced those too: the picture went black at each kill, and with a new MetalFX scaler made again and again the game's memory grew to 7 GB and it hung. MetalFX now only takes a pass that writes the whole picture, and only a few scalers are ever made.
- **Palm trunks and hanging fronds on Dust2: whole again (KosmicKrisp).** CS2 draws foliage twice -- first only its depth, then its colour where the depth matches exactly. Metal's fast math could round the two positions a hair apart, and those pixels were never drawn: black clusters on the trunks, dotted fronds. Vertex shaders are now compiled without that fusion of operations; measured at the same frame rate (71-74 fps on Dust2). A counterpart for MoltenVK is included but off until it is measured (`LXRT_VK_INVARIANT_POSITION=1`).
- **Steam no longer grows by about a gigabyte an hour.** The Steam client tried to start a USB library for controllers four times a second; it could never work, and each attempt left memory behind in SteamARM's runtime. After a couple of hours the Mac ran out of memory and games slowed down. The attempt is now switched off (controllers keep working: they reach Steam and games through SteamARM's own input service), and the runtime frees that memory anyway when a library is unloaded.
- One-sample alpha-to-coverage (cut-outs without MSAA) is now a clean cut at half transparency on both drivers.

Everything in 0.3.45 is included.

**Tested on a real Mac (M4, macOS 27):** Dust2 on KosmicKrisp, palm trunks whole at 70-74 fps; MetalFX only on full-picture passes (Vulkan FSR tests pass); 2000 library load/unload cycles with no memory growth in the runtime; settings tests pass.

Update: drag the new SteamARM.app over the old one, open it, and click **Instalar** in the banner.
