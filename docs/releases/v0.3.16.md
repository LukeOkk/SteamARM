**A crash when a program loads Vulkan a second time is fixed.** A Linux program that loaded the Vulkan library, closed it and loaded it again crashed inside the x86 translator (64- and 32-bit alike): the second copy landed elsewhere in memory while the translator still pointed at the first. Steam's own 32-bit client does exactly that when OpenGL goes through Zink. SteamARM's Vulkan bridge now stays loaded once a program has loaded it, so a second load is the same copy. Measured: three loads in a row, 64- and 32-bit; x86 Steam reached its main window 8 times in 8.

**Setup finishes even if a self-test fails.** When one of Setup's final self-tests failed (a stress test fails now and then), Setup stopped before recording that it was done, and the launcher kept offering **Instalar**. A failed self-test is now reported and Setup completes.

**OpenGL for native Linux games (advanced, untested with games):** `docs/USAGE.md` explains how one game's Steam **Launch options** can ask for OpenGL 4.5 on the GPU through Zink.

Everything in 0.3.15 is included.

**Tested on a real Mac (M4, macOS 27):** Vulkan and OpenGL 6/6 (the new reload test included); Windows programs 14/14 (DXVK, VKD3D-Proton and WineD3D); native ARM64 Steam reached its sign-in window 3 times in 3 (15 s). Record: `benchmarks/stage39-wined3d-gl45.txt` (section 5).
