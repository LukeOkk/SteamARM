**Games are no longer held to half the display's rate.** A game that asks to present without V-Sync now really does: Counter-Strike 2 used to stop at 82.5 frames per second on a 165 Hz display (and fell to 55 or 41 whenever a frame took a little longer). In a match against bots it now runs at a median of 75-83, with peaks of 91-107.

What was done:
- **The window's layer made every program wait for the display**, whatever it asked for: the layer is shown by SteamARM's X server, another process, which takes one image per refresh. For games that ask for no V-Sync, SteamARM now keeps the game drawing and shows the newest finished image at each refresh, without tearing. Games that ask for V-Sync are not affected.

**Still not there:** 170-200 frames per second in Counter-Strike 2. The GPU is now busy 99 % of the time in a match (the game issues about 135 render passes per frame, each with a fixed cost on Apple's GPUs), and the game's main thread is translated x86 code. Lower video settings in the game help the first.

Everything in 0.3.25 is included.

**Tested on a real Mac (M4, macOS 27):** Vulkan tests 14/14, Windows tests 21/21, runtime tests 106/106, Direct3D 11/12 through Proton 157/159 fps (V-Sync on, unchanged). Measurements: `benchmarks/stage52-mailbox-present.txt`.

**Pre-release.** If a game misbehaves without V-Sync, start SteamARM with `LXRT_VK_MAILBOX=0` to get the old behaviour, and tell us.

Update: drag the new SteamARM.app over the old one, open it, and click **Instalar** in the banner.
