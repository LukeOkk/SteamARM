**Android apps open in a Mac window, with no virtual machine (experimental).** An APK added with **Añadir APK** now opens from its card: SteamARM starts an Android 11 session (the x86-64 build of Waydroid's LineageOS 18.1, run under FEX), installs the app with Android's own package manager and starts it; its window appears in a macOS window. Measured on a Mac mini M4: Android is up in 17–27 s when started before, about 45 s the first time; Simple Solitaire Collection (F-Droid) opened, took a tap and dealt a game. Mouse movement from the Mac reaches Android; real clicks and keys are not verified yet. **What runs:** apps with no native code, or with x86-64 native code. **What does not:** apps whose native code is only arm64-v8a (Android's arm64 ART needs its heap below 4 GiB, which macOS does not allow; a design to lift that is in `docs/ART_HEAP_ABOVE_4GB.md`, not built yet), 32-bit ARM apps, sound, network and camera. Rendering is done on the CPU. The Android root is not set up by **Instalar**: the card says how to create it (`scripts/mkandroidroot.sh --arch x86_64`, which downloads Waydroid's public image, then `--emu`, and `scripts/mkwestonroot.sh`).

**Google Play Store: tooling only.** SteamARM never downloads, bundles or redistributes Google's apps, never fakes device certification and never bypasses Play Integrity. `scripts/android-gapps.py` checks a GApps package you supply yourself and prepares it as an overlay; `docs/PLAY_STORE_SETUP.md` explains the steps, including Google's own registration page for uncertified devices. Play Store has not been run yet: networking and account services are still missing in the Android session.

**Heroic Games Launcher runs natively on ARM64.** Its linux-arm64 build (Electron 43, assembled from official release files; identical to an arm64 build of its source) runs in the ARM64 root with no FEX: window in about 4–5 s, settings, clean close and reopen. V8's optimizing compiler works again (it had to be switched off; a Heroic installed with 0.3.5's launcher keeps it off until reinstalled), after a fix in how the runtime rewrites jumps through register x18. Store sign-in, downloads and games in Heroic are not verified; Amazon's helper does not run.

**Runtime:**
- lxrun is now linked so that macOS keeps register x18 for it (as for programs built for macOS 12.3), which Linux JIT compilers (Java, V8, llvmpipe) need. If that link fails, the build falls back and says so.
- FEX gains fixes that every x86 program benefits from: signals it deferred are delivered again (a shell could hang forever), the intermittent hang of shells under FEX is gone (0 in 960 runs), code rewritten through a second mapping is retranslated, and 32-bit Android programs run.
- Android pieces in userspace: binder (with Android's own `servicemanager`), system properties, Android user and group ids, and a minimal init that reads the image's own `.rc` files. An adversarial review of that code fixed 10 defects.
- Fixes found on the way: `sendfile`/`splice`, per-4 KiB `mremap` and file mappings at 4 KiB offsets, `msync`, SysV shared memory kept while attached, `/proc/self/exe`, and an `inotify` and `eventfd` pair that Qt needs.

**Launcher:**
- A second native ARM64 Steam entry on the Steam Frame root starts again after a restart once its volume is attached; with the volume missing, the entry now refuses with the reason instead of leaving `/tmp/lxrt-arm64root` broken.
- The memory guard counts an Android session's processes.

**Tested on a real Mac (M4, macOS 27) on the release commit's runtime:** tests/elf 86/86; i386 18/18; Windows D3D9/11/12 probes 11/11 at 159–161 fps; Steam's container (sound, XInput) 2/2; Vulkan device 2/2; ARM64 client checks 4/4; Android 76–77 passed with 3 expected failures (arm64 ART's heap, 32-bit bionic's 16-bit thread ids, the headless boot's display wall); launcher core all passing. From the launcher: native ARM64 Steam sign-in window at 16 s (Fedora root) and 35 s (Steam Frame root); x86 Steam main window at 125 s in 2 of 3 starts that day (the first, right after other sessions, showed no window in 5 minutes; stop and start it again). Records: `benchmarks/stage24-*.txt` to `stage28-*.txt`.

**Pre-release.** Games are still not verified. The working Steam route is the x86 client under FEX with x86 Proton; Proton ARM64 does not run on macOS.

Update: drag the new SteamARM.app over the old one, open it, and click **Instalar** in the banner (it rebuilds the runtime and FEX with the new patches).
