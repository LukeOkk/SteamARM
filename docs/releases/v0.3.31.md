**Steam starts reliably: no more web-helper crashes or a main window that never appears.**

What was done:
- **Steam's web helper crashed in most starts, and sometimes the main window never came.** Steam's web helper makes a Vulkan device, drops it, and makes the one it draws with. SteamARM's presenter (the V-Sync mailbox) signalled the first frame of the second device on the first device's queue — already destroyed — and the graphics driver crashed 13-17 seconds into the start. Queues are now kept per device and forgotten when the device goes. New test: a destroyed device followed by a fresh swapchain (crashed before, 60 frames now, on KosmicKrisp and MoltenVK).
- **After many Steam restarts, Steam stopped starting at all** (it died about 30 seconds in, no window). SteamARM's X server never freed the OpenGL resources that Steam's processes left behind when they closed: about 15 OpenGL contexts and 37 graphics surfaces per Steam start, until macOS refused to create any more contexts. The X server now frees them; over repeated Steam starts its memory stays flat (83 MB) instead of growing 6.5 MB per start. Restarting SteamARM's X server also cleared it before.
- **About one start in ten lost a Steam helper process** to a memory error inside SteamARM's runtime while a library was being loaded (a page past the end of the library's file was written to). The runtime now checks a page can be read in full before writing into it, and repairs it if not. In the thirty Steam starts that followed, six such pages were repaired instead of crashing a process.
- **PipeWire clients can start.** Steam runs `wpctl` (PipeWire's control tool) for its audio settings; it crashed every time — 180 times in fifteen starts — because the runtime lacked the futex operations behind priority-inheritance mutexes. They are now there (without the priority boost itself, which macOS cannot express). `wpctl` now reports that no PipeWire server is running instead of crashing. Game sound and the microphone go through PulseAudio as before (48 kHz, high-quality resampling).
- **Better crash reports:** when the runtime itself faults, the report also goes to `/tmp/lxrt-faults.log` (program path only, never its arguments), with what was mapped at the faulting address.

Everything in 0.3.30 is included.

**Tested on a real Mac (M4, macOS 27):** runtime tests 108/108 (one new), Vulkan tests 34/34 (one new), Python tests passing; dozens of Steam starts in a row (one in about sixty still stalls at start-up and needs a restart; under investigation).

Update: drag the new SteamARM.app over the old one, open it, and click **Instalar** in the banner.
